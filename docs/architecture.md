# minColor — architecture

The technical model behind the panel and the engine. For installing and using minColor see the
[README](../README.md); for building and releasing see [building.md](building.md).

## Three layers

1. **Meaning** — the effect names (`minColor: X → working`, `view X`, `render X`, …), the working
   space, and the contents of the pinned config. This is the durable state; it lives in the
   project.
2. **Configuration** — the pin: which config file the project points at, and the preset it
   belongs to.
3. **Executor** — whose compiled effect interprets the names: Adobe's native OCIO Color Space
   Transform or the minColor CST plug-in. Both render pixel-identical; they differ operationally
   (crash immunity on config switches, late binding, a pinned OCIO version, an install
   requirement). Users touch this layer only at the packaging boundary.

## Identity import, single authority

Every config's Default file rule, `default` role and working space agree, so all footage imports
untransformed — After Effects never guesses. Interpretation happens once, on the timeline, as a
per-layer effect. Footage-level assignments are never used; Migrate strips them (harvesting the
old assignments as suggestions).

**Effect grammar** (display names are the store; the plug-in's "Sync From Names" derives effect
state from them):

| name | meaning |
|---|---|
| `minColor: <space> → working` | interpret a footage layer |
| `minColor: view <space>` | the comp's VIEW guide layer (viewport only, never renders) |
| `minColor: render <space>` | the comp's RENDER layer (renders: working → delivery encoding) |
| `minColor: look <name>` | an OCIO look, applied before the transform on the same layer |
| `minColor: contain <space>` | a precomp's output is media in that space; walks do not descend (name-level only) |

Interpret timeline and Migrate finish by ensuring both utility layers on the active comp, from
the panel's current View and Render choices, with the view enabled and the render off.

## Config family

One OCIO config per working-space preset, generated by `config/generate.py` from a vendored
Blender 5.2 master (AgX, ACES 1.3/2.0, cameras) with a QCView EDR patch, then down-levelled to
OCIO 2.4 for After Effects. Filenames are content-hashed (`config-<preset>-<hash>.ocio`); the
hash is the config's identity and the store is **append-only forever** — a project pinned to a
hash must always find it.

- **Linear family** — ACEScg, ACES2065-1, Linear Rec.709, Linear Rec.2020: scene-linear working
  space, tone-mapped views (ACES, AgX, Filmic…), looks, EDR displays for QCView.
- **SDR** — working space `Rec.709 Gamma 2.2` (Rec.709 primaries, pure 2.2: what a desktop
  display does). SDR is SDR: working values are the deliverable; Rec.709 video is working-native
  (no effect); sRGB stills get the exact sRGB→2.2 re-encode; linear/log sources get plain
  inverse-OETF conversions, no tone mapping (that is what the linear presets are for). Only
  Standard/Raw views, no looks; tone-mapped targets would be double transforms on display-referred
  pixels. Every colourspace is self-contained (direct matrices, no hop through the XYZ interchange
  space).
- **Views and renders** (all presets): `macOS Desktop View` (P3 primaries, pure 2.2 — AE's macOS
  viewport surface) and `macOS Video View` (the same after a BT.1886 encode + desktop sRGB decode:
  how a 709 delivery plays through QuickTime-style pipelines); `Windows Desktop View` (= sRGB),
  `Windows Video View` (= Rec.1886). All four are view-only. `Desktop Render` (= sRGB) and
  `Video Render` (= Rec.1886) are render-only. A render layer's output is shown raw in the
  viewport, so a Video Render looks lifted on a desktop display by construction.
- The older `macOS View Only` display stays in every config because After Effects stores the
  viewer's display choice by name; it is not offered, and effects carrying it are renamed on
  migrate. Displays are added, never renamed.
- Per-preset menus (`presets.json`): input / view / render lists, view-only names, labels. The
  panel filters every list through the **pinned** config, so a project pinned to an older hash is
  never offered a space its config lacks (the plug-in would pass such an effect through). The
  Doctor reports "update available" when the pin is behind; Migrate to the same preset updates it.

## Stores and pins

- **Central store**: `…/Adobe/Common/Plug-ins/7.0/MediaCore/minColor/configs` beside the plug-in.
  Projects pin the absolute path. The plug-in locates the store relative to its own binary.
- **Passport**: each effect's sequence data carries the config's hashed filename and the working
  space. If the project's pin is dead (typically after crossing platforms), the plug-in resolves
  the config from the local store and renders identically, including under aerender. The panel's
  Doctor re-pins the project and records the repair.
- **Provenance**: preset, config identity and tool versions are stamped into the project's XMP;
  repairs and migrations key off it, and projects without it are never touched.
- **Settings** (dropdown state, extension table, repair history) live outside the install:
  `/Users/Shared/minColor/settings/`, `C:\ProgramData\minColor\settings\`.

## Archive and Package

- **Archive** — freeze dependencies, keep working: materialize a sidecar (config + LUTs) next to
  the project, `provenance.json`, and a golden reference frame (a ramp through sRGB→working) that
  future machines can diff to *detect* engine drift. Purely additive; pin and effects untouched.
  Run at milestones.
- **Package for any AE** — the project leaves the ecosystem: Archive plus translating every
  effect to Adobe-native and pinning the sidecar. Opens on any After Effects 2025+ with zero
  minColor; reversible via Adopt. Package a version increment, not the working copy.
- **Archival contract**: append-only-forever config store (the install is the config archive),
  provenance names exact versions, the plug-in pins the colour engine (statically linked OCIO).

## The plug-in

`minColor CST` (matchName `MINC CST`) is a SmartFX effect that stores only a colourspace name and
a direction. At render it reads the project's current OCIO config and working space through the
Color Settings suite and processes with its own statically linked OCIO 2.5.2. Instance ids are
unique across sessions (the render-side registry is keyed by them); "Sync From Names" repairs any
duplicate it meets. Status ladder: OK · OK (passport) · pass-through (OCIO off / unknown space /
config error), shown as a chip in the effect controls.
